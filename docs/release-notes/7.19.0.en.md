## What's new

- One-line installers for OpenClaw hosts: `install-plugin.sh` (Linux, macOS, WSL) and `install-plugin.ps1` (Windows, beta). They verify a minisign-signed feed, snapshot the memory store, install or update through `openclaw plugins`, and roll back on a failed check. Also `--adopt-legacy` (rsync deploys), `--rollback`, `--uninstall`.
- `openclaw plur1bus selftest` checks the plugin in a throw-away store.
- Hermes host mode: `--host hermes` (`-Host hermes` in the `.ps1`) installs the memory provider into a Hermes agent (0.21.4 or newer) with a local sidecar that holds the store; its binary is pinned by the feed and SHA-256 checked. One agent per Hermes home; another provider is replaced only with `--replace-provider`. A Node-less machine gets a pinned portable Node 24.21.0.
- Release artefacts carry build attestations; the npm package, when published, carries provenance.
- Store snapshots can live outside the OpenClaw state directory (`snapshotsDir`).

## Fixes

- Store snapshots retry when a table is compacted during the copy and refuse a store inside the harness home.
- A fresh state directory without `openclaw.json` is no longer an invalid config.

## Upgrade notes

- No store migration; existing installs keep configuration and embedding choice.
- An install from `install-memory-system.sh` needs `--adopt-legacy`; disable the `protect-plur1bus-deploy.sh` cron line first.
- Details: `docs/distribution.md`.

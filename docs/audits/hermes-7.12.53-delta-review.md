## Reachable Hermes adaptations

| Upstream contract | Native implementation / meaningful difference |
| --- | --- |
| Skill auto-apply mode, review benefit and mined-skills list (.48) | `skill_workshop.py` supports `skillWorkshop.autoApply: host|on|off`. `host` remains manual because Hermes has no equivalent OpenClaw workshop-policy RPC. Explicit `on` requires a bound private profile, at least three current trusted observations and confidence at least 0.6. Desktop and web Workshop lists show benefit, category, confidence, evidence count, date and state. |
| Benefit backfill without rewriting approved skill bytes (.49) | `/plur1bus skills benefit-backfill [LIMIT]` fills advisory benefit text. Versioned immutable proposal material retains the original rendered benefit. Existing approved revisions and native skill hashes remain valid. Backend failures are item-local and truthful. |
| Nightly mining after maintenance, tolerant rate gate (.49–.50) | `jobs.py` invokes native mining after maintenance in daily/all runs, retaining Hermes's existing native schedule. Mining uses a 20-hour gate; daily consolidation uses 12 hours so small schedule jitter does not skip the next day. No duplicate OpenClaw cron job or borrowed gateway port. |
| Avoid repeated model calls for identical evidence (.50) | Scope-owned persistent fingerprint memo, bounded to 300 entries, covers evidence IDs, content hashes and trust state. A durable scoped keyset cursor visits at most 100 rows per run, continuing past the first window and wrapping at EOF. At most three backend calls/candidates; failed clusters are retried before advancing. |
| Host-approved skill paths and safe withdrawal (.48, .51) | Native publication uses the selected profile's `skills` tree, not OpenClaw's workshop directory. Revision-bound rejection and withdrawal are exposed in Controls, Desktop and web. Withdrawal archives exact generated bytes, refuses manual changes/symlinks, and retains provenance/audit records. |
| Legal evidence confirmation transitions and document IDs (.52) | Native scoped compare-and-set transitions, checked against current content/status/role/expiry. System approval only promotes observed to corroborated; human legacy confirmation performs one blank-to-observed transition. Untrusted/disputed/invalidated evidence is not promoted. Non-UUID document IDs are read-only evidence and skipped for mutation. |
| Finish partial activation instead of returning early (.53) | Publication records a durable partial state before evidence promotion; repeating publish retries unfinished confirmations without overwriting changed skill files or repeating completed promotions. Both UIs offer an explicit finish-confirmation action. |

## Hermes-specific integration retained and repaired

- Keep all prior native maintenance, partition guards, snapshots, retrieval
  providers, staged dimension migration, owner/profile isolation, provenance,
  Obsidian review, critical delivery, and background lifecycle implementations.
  The JavaScript merge alone is not evidence for their native behavior.
- Install dashboard backend, unified Desktop contribution and the appropriate
  materialized UI. Activation includes persistent-memory enablement and both
  plugin allow/deny lists. Files-only installation stays files-only.
- Resolve Controls configuration and skill publication from the host's
  request-local profile home, including multiplexed profile switches; standalone
  processes honor `HERMES_HOME`. Explicit caller binding takes precedence.
- Desktop contributes a real route on modern SDKs and retains the legacy
  open-page fallback. Explicitly disabled profiles hide the entry; unknown/loading
  state is not incorrectly treated as disabled. Backend authorization remains
  authoritative while the visibility probe is pending.
- Named-profile CLI activation passes `--profile NAME` explicitly rather than
  accidentally activating the sticky profile. Existing model/provider settings,
  memory data, and OpenClaw `main` / npm `latest` remain out of scope.

## Verification boundary

Intermediate local run: 941 Python tests and 135 subtests passed before the
subsequent independent-review fixes. Follow-up native Workshop/Controls/jobs:
55 tests and 11 subtests passed. Desktop ESM harness passed; dashboard/jobs
37 tests passed. The repeated complete Node run passed 4,638 of 4,714 tests,
with 76 conditional skips and zero failures. The first run's ephemeral
loopback-port collision did not recur. Lint and Python dependency checks passed.
Final source and platform package tests must be repeated after the final merge.

Independent review found and fixed two further integration defects: a stale
root Desktop plugin could take precedence over profile payloads, and mining
could stop progressing after its initial evidence window. Installer apply and
rollback were checked against the actual installed Hermes reconciliation helper
in temporary homes, preserving additional UI files. Real LanceDB tests reach all
104 reverse-inserted evidence rows, retry a failed cluster, and approve opaque
document IDs beyond the first page without mutating their trust status.

The companion community Hub tap is published at
`Cyb3rb1ade/plur1bus-hermes-skills` (commit `97fd648`). Actual Hermes Hub search,
fetch, safe scan and isolated install matched the source skill SHA-256
`1869223dc5573c0a37efe1ae7ddc8cd8846490692f6f39fc88f37d635a0faf92`.
This does not publish or install the candidate plugin packages.

`npm audit` reports four dependency-tree findings (two moderate, two high),
all in the optional JavaScript Hugging Face / ONNX / sharp chain. Core audit
with `--omit=optional` reports zero. Those JavaScript dependencies are not used
by the native Python Hermes provider. These are not represented as a clean

this port. Final release notes must retain this distinction if still present.

Windows signing, actual model quality, productive profile installation and
historical guest-VM tests are separate evidence categories. No current claim is

## Hermes-specific behavior preserved

The port retains profile selection and isolation, active-writer namespace
routing, maintenance/retry guards, snapshots, staged model/dimension migration,
Obsidian review, critical delivery, background jobs and platform installers.
Controls and native skill publication resolve the host's active profile per
request rather than assuming the default home.

Both the unified and existing app-wide Desktop entries are handled by the
installer. Shared frontend changes are declared in the plan and recoverable;
unselected profile configuration/backend data are not changed. Retired
materialization markers prevent Hermes restart from deleting sibling UI files.
Persistent-memory enablement is checked for activation and navigation.

## Intentional host differences

- OpenClaw's isolated-completion harness, workshop RPCs, host cron transport and
  default auto-apply policy are not Hermes APIs. Equivalent native behavior is
  provided where possible; `autoApply: host` stays manual, explicit `on` opts in.
- Native episode identity includes content, role, owner, session and time.
  Copying the upstream ID-only shortcut would incorrectly skip revised evidence.
- Model diagnosis is explicitly opt-in and may contain redacted prompt fragments.
  Normal operation does not create diagnostic files.
- A community [Hermes Skills Hub tap](https://github.com/Cyb3rb1ade/plur1bus-hermes-skills)
  distributes installation/diagnostic guidance, not native plugin binaries.

## Evidence boundary

Independent review also reproduced three defects in the upstream .55 changes:
an all-covered episode retry can replace the persisted open-episode identity,
the opt-in diagnostic sink redacts `message` but not `name`/`code`, and a throwing
foreign `message` getter can escape the model router's fail-soft error path.
Regression-tested fixes are incorporated from commit
`94484bf84ad822c3c4aa00e2f2a8807a347a6af7`, submitted as
[upstream PR #151](https://github.com/Cyb3rb1ade/openclaw-plur1bus-memory/pull/151).
The native episode path uses content-bound append-only derived receipts and does
not share the OpenClaw open-episode state machine.

The installer review additionally fixed shared UI downgrade prevention across
disjoint profile selections. A separate rollback-bound shared UI receipt prevents
this installer from replacing a newer app-wide UI while installing an older bundle
for another profile; it does not falsify the unselected backend's version.
Already shipped older installer binaries cannot be retroactively changed.

Independent native diagnostic review also removed a waiting thread mutex: a busy
diagnostic writer now skips only the optional record, without delaying another
model failure fallback. Real Windows ACL/reparse/rotation tests run in the Windows
matrix rather than being represented by POSIX tests or mock-only evidence.

The .53 integration's final local gates were 967 Python tests plus 135 subtests,
4,640 Node passes with 76 conditional skips, and 30 dashboard tests. Those are
historical baseline results, not certification of the .55 source or packages.
The final .55 acceptance record and source-pinned platform receipts must be
checked separately. No productive profile install, model switch or memory
migration is implied by this source port.

The optional JavaScript Hugging Face/ONNX/sharp dependency chain still reports
four affected package entries (two underlying advisories); the core audit with
optional dependencies omitted is clean. Native Hermes does not use that chain.
The dependency findings are reported in
[upstream issue #150](https://github.com/Cyb3rb1ade/openclaw-plur1bus-memory/issues/150);
this is not a claim of demonstrated PLUR1BUS exploit reachability. Audit and
signing status must be reported independently for final artifacts.

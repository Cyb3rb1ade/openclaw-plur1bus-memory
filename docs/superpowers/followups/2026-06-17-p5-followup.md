# P5 Temporal Provenance + Operational Action Guard — follow-up notes

## What changed

- Added `lib/temporal-provenance.js` with pure, deterministic helpers for memory
  age, freshness, operational detection, operational-risk classification, and
  live-verification gating.
- `lib/relevant-memory-context.js` now renders temporal attributes on each
  `<memory-record>` (`created-at`, `age`, `freshness`, `operational`,
  `operational-risk`, `requires-live-verification`) and inserts an
  `<operational-memory-warning>` block when stale or unknown-age operational
  memories are present.
- `lib/recall-decision-trace.js` persists `temporal` metadata on candidates and
  decisions, and `enrichTraceWithTemporalProvenance` adds guard records for
  stale/unknown operational decisions.
- `index.js` passes `updatedAt` / `lastRetrievedAt` through to recalled items,
  enriches the decision trace with temporal provenance, and passes `now` to the
  context formatter.
- Added regression tests:
  - `tests/temporal-provenance.test.js`
  - `tests/relevant-memory-context-temporal.test.js`
  - `tests/recall-decision-trace-temporal.test.js`
  - `tests/operational-action-guard.test.js`
- Added `docs/runbooks/operational-live-verification.md`.

## Verification run

- `npm test` — all tests pass.
- `npm run lint` — syntax checks clean.
- `npm audit` — no vulnerabilities.
- `git diff --check` — no whitespace errors.

## Known limitations / future work

- Timestamps depend on existing memory fields (`createdAt`, `updatedAt`,
  `lastRetrievedAt`). If a store lacks these fields, the memory is treated as
  `freshness="unknown"` and triggers live verification for operational content.
- Operational keyword matching is simple substring search. Domain-specific
  synonyms or multilingual terms may need expansion.
- The warning is prompt-level only; it does not block tool execution at runtime.
  A runtime policy hook could be added later to hard-refuse destructive actions
  when `requires-live-verification="true"` memories are present.
- Host-level state (crontab, systemd) was not verified on the mac-clone because
  production credentials/SSH are not available in this environment. The runbook
  documents the live commands that should be used when access is available.

## Rollback

All changes are additive. Reverting this branch restores the previous context
format and removes the temporal attributes and warning block.

# Hermes 7.12.44 Canonical Episodes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make short conversations produce evolving canonical episodes with journal-backed metadata that actual Hermes consumers use.

**Architecture:** Keep durable journal rows authoritative. Append versioned canonical episode records, resolve latest revisions after scope filtering, and enrich those canonical records off the prompt path. Keep narrative audit records but do not mistake shadow output for feature delivery.

**Tech Stack:** Python, JSONL, scoped native domain/jobs, Obsidian managed files.

**Spec:** `docs/superpowers/specs/2026-09-11-hermes-7.12.44-design.md`

## Task 1: Latest canonical episode projection and continuity

**Files:** create `plur1bus-hermes/src/plur1bus_hermes/episodes.py`; modify
`domain.py` on_turn, run_light_dream, maintain_obsidian, status; modify
`proactive.py` afterthought; create `tests/test_episode_continuity.py`.

**Interfaces:**
- `latest_episodes(rows: list[dict]) -> list[dict]` resolves latest record per
  `(agentId, scopeKey, sessionId, id)`; preserve unique legacy records without
  session fields, never collapse across owners. Caller authorizes rows first.
- `domain._episodes_for_scope(selector) -> list[dict]` wraps existing scoped
  reads then revision projection. Use at all three domain consumers.
- Within writer lock, new durable turns extend latest open episode for exact
  scope/session if last-to-first gap is below 30 minutes and <=50 total turns.
  Otherwise create next episode. Deduplicate turn IDs before counting.
- Canonical fields retain `id`, `turnIds`, original `startTime`, new `endTime`,
  `sessionId`, `revision`, ownership/visibility; `memoryIds` must not falsely
  label journal IDs as LanceDB IDs. Document the native reference distinction.

## Task 2: Validated short-turn enrichment on canonical episodes

**Files:** modify `episode_narrative.py`, `domain.py` run_episode_narratives;
tests `test_episode_narrative.py`, `test_episode_continuity.py`.

**Interfaces:**
- Keep `enrich(turns, complete_json)` but lower minimum to 2; preserve <=50 turns,
  unique existing evidence IDs, untrusted conversation framing and field caps.
- Prompt content budget: newest turns first for selection, at most 600 chars per
  turn and 6000 total conversation characters, rendered back in chronological order.
- Add bounded topics, participants, mentioned, voiceSpeakers and dialogue emotion
  metadata. Allowed emotion labels come from existing native cognition vocabulary;
  low/medium/high intensity maps to 0.3/0.55/0.8. Reject non-finite/out-of-range data.
- Participants come from authoritative journal roles/name attribution, not model
  `people`. Model people become mentioned, excluding participants. Voice labels
  remain untrusted attribution and cannot modify ownership.
- Enrichment returns evidence fingerprint. Under writer lock, re-read canonical
  episode/journal before appending new revision; changed fingerprint means skip
  stale result. Keep slow inference outside the writer critical section.

## Task 3: Scoped episode rebuild with preview and evidence checks

**Files:** modify `domain.py`, `operator_cli.py`; create
`tests/test_episode_rebuild.py`; update command documentation and audit.

**Interfaces:**
- Local operator subcommand `episodes-rebuild`, readonly preview by default,
  `--days N` clamped 1–365 with default 1; explicit `--apply` commits.
- Preview binds agent/scope, selected episode IDs/revisions and source journal
  fingerprints. Apply rejects source drift and foreign/malformed references.
- Prefer exact turn IDs. Legacy fallback uses start/end +/-2 seconds only inside
  the same known session and scope; unknown/ambiguous session skips with reason.
- Rebuild retains episode identity, increments revision and does not alter open
  episode ownership or capture cursor. Latest projection resolves new revision.
- Managed single-episode card replacement preserves manual content; ambiguous
  multi-episode legacy cards remain untouched and receive a separate output.

- [ ] Test dry-run before any apply: files and database unchanged, counts match
  selected date/scope window. Test id-based selection and time-window fallback
  separately using fixed journal timestamps and legacy mismatched IDs.
- [ ] Observe absent-command/behavior RED; implement preview/apply using current
  operator validation/confirmation patterns, no generic arbitrary-path executor.
- [ ] Test wrong scope, changed revision, ambiguous session, forged ID, manual
  card, failed enrichment and interrupted/repeated apply. Failures must leave
  journal and original canonical episode readable; report reasons honestly.
- [ ] Run operator, episode, Obsidian and scope suites; update audit rows only
  with actual callable commands/tests; commit and request task/whole-plan review.

## Review boundary

Canonical episodes can be implemented safely without a new host delivery hook.
Generic reply outcomes, Neo vector/index storage and full persona evolution are
different plans. Neither status counts nor narrative-file existence alone proves
this plan complete: canonical consumer and rebuild tests are mandatory.

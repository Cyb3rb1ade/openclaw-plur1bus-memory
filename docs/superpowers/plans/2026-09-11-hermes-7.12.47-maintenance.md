# Hermes 7.12.47 Native Maintenance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** Port bounded, partition-safe decay and optimize conflict handling.
**Architecture:** Retain Hermes scopeKey and metadataJson storage. Compute a
bounded page under the writer lock and commit strength, timestamp and feedback
identities together; never copy upstream's unsafe two-commit fallback. Shared
physical optimization supports explicit manual and existing scheduled contexts.
**Tech Stack:** Python, LanceDB 0.34.0, existing file locks/cursors, pytest.
**Spec:** `docs/superpowers/specs/2026-09-11-hermes-7.12.47-addendum.md`

## Global Constraints

- No production data/config changes, models, publication or remote mutations.
- Exact owner scope before query limits and before every write; preserve native
  private/workspace/user/chat semantics. No ACL relaxation from incidental fields.
- No table overwrite, insertion of missing metadata or deletion during decay.
- Preserve zero strength, core/neverForget exemption, unrelated metadata and
  exactly-once feedback. No retry after an uncertain mutation without evidence.
- Budget is admission/elapsed control, not claimed cancellation of Rust I/O.
- All test fixtures are disposable; no HOME override.

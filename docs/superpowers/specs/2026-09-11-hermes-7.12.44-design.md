# PLUR1BUS 7.12.44: native Hermes port and full feature audit

Date: 2026-09-11. Status: approved by user ("passt! Leg los").

## Objective and source boundaries

Port the shared behavior added after OpenClaw 7.12.7 to Hermes, audit older
feature gaps, and preserve Hermes-specific functionality. The deliverable is
an unpublished, tested candidate, not a production installation or release.

- Upstream baseline: `v7.12.7`.
- Pinned upstream candidate: `a3f48f28ac647e81c5260e8a1dbab7977bf9fb51`
  (package version 7.12.44, includes functional commit `c59366f`).
- Hermes baseline: `c12ec2bba63d74ac8add8782ab6761472b4149c6`,
  released as `7.12.7-hermes.4`.
- Working branch: `codex/hermes-port-7.12.44`.
- The upstream delta contains 90 changed files. Counts and changelog headings
  are inventory inputs, not proof of feature equivalence.
- Later upstream changes require a separately recorded delta review; do not
  silently move the audited source reference while implementing.

No publication, tags, registry changes, productive profile activation, model
downloads into productive installations, or live memory migrations are included.
Do not weaken existing safeguards merely to mark a feature complete.

## Chosen architecture

Retain the native Python MemoryProvider, controls, storage routes, dashboard
and distribution stack. Integrate upstream JavaScript without discarding
Hermes additions, then implement the relevant behavior in reachable native
paths. Keeping JavaScript in the package does not constitute a Python port.

Hermes continues to own sessions, channels, routing, approvals and chat-model
selection. OpenClaw dispatch/SDK/cron details map to verified Hermes lifecycle
contracts rather than fabricated compatibility callbacks. The separate
`.openclaw/extensions/emotional-state-injector` is assessed explicitly as a
companion extension, not silently installed as a Hermes dependency.

Rejected alternatives: a delta-only port leaves historical gaps unexamined;
a shared-runtime rewrite increases deployment and lifecycle risk without being
required for this update. This design is one compatibility initiative with
ordered work packages, not a replacement architecture.

## Traceability and definition of parity

Produce a versioned audit matrix and update `plur1bus_hermes.parity` from
evidence. Each contract records upstream commit/function, native entry point,
configuration/defaults, ownership and failure semantics, tests and remaining
limits. Inventory all commits since the baseline, including non-release fixes
and scripts, not only changelog summaries.

Also enumerate the full upstream feature surface: tools, commands, hooks,
configuration, jobs, storage writers, migration/repair operations and UI.
Reassess every existing partial/not-ported/excluded entry against live code.
Historical matrix entries may be stale and are not automatically accepted.

Statuses distinguish verified native equivalence, implemented but unverified,
partial coverage, missing functionality and genuinely host-specific behavior.
Host-specific classification requires an explanation of the unavailable host
contract and whether a useful native equivalent exists. No status upgrade based
only on package presence, test totals or version strings.

## Work packages and contracts

### 1. Storage, capture, Neo and lifecycle identity

Review capture batch budgets, bounded drain/cancellation, durable embedding
retries, stable turn IDs, process-wide resource ownership and reply outcomes.
Journal, episodes and derived records must refer to the same canonical scoped
turn identity. Restarts/retries must not duplicate durable turns or outcomes.
Voice/image input must participate without deriving authority from body text.

Assess Neo vector sidecars, global candidate search, metadata indexing,
warm-up, persistent cap checks and canonical status/doctor routes. Native
equivalents must remain bounded and read the same scoped store as writers.
Migration and rebuild operations require idempotence, resumability and explicit
dry-run/apply boundaries; empty or failed reads cannot justify data deletion.

### 2. Recall, corrections and knowledge

Port applicable ACL diagnostics and partition-aware maintenance without any
query fallback that removes authorization predicates. Preserve metadata and
lineage across corrections, including the semantics underlying JS BigInt fixes
even where Python integers make the language-specific fix unnecessary.

Temporal duration phrases such as 'bis heute' must not accidentally become a
single-day query. A heuristic temporal filter may fall back to the already
authorized, lifecycle-valid candidate set if it would remove every result.
It must never undo ACL, tombstone, TTL, explicit validAt or explicit query bounds.

Knowledge promotion pruning requires a successful scoped lookup of the exact
IDs under consideration. Query failure or truncation must leave unexamined
queue entries intact. Preserve rolling budgets, source revalidation, durable
deduplication and confirmation policy while adapting applicable upstream fixes.

### 3. Episodes, persona and cognition

Episodic state is partitioned by agent, scope and session. Continue an existing
episode within the 30-minute gap and 50-turn cap, use stable episode identity
and versioned updates, and link only to actual journal turns. Rebuild operates
on explicit scoped selections; legacy time-window fallback must not mix sessions
or expose foreign turns. Preserve manual and legacy multi-episode files.

Port bounded narrative enrichment, recent-turn prompt budgeting, validated
topics, conversation emotion/intensity, and participants versus mentioned people.
Voice-speaker extraction is descriptive metadata, never authentication. Untrusted
transcript prefixes cannot grant ACL or confirmation privileges. Model errors
leave durable capture intact and yield explicit bounded fallback behavior.

Persona evolution preserves seed/manual text and learns only in managed regions.
Add configurable directive capacity, ADD/REPLACE/NONE semantics, duplicate-marker
handling, evidence consumption, positive/negative outcome context, heartbeat
exclusion and persisted cooldown/minimum-outcome guards. Adapt scheduling to
native job ownership; preserve operator-custom schedules and existing opt-ins.

Review emotion-refinement tier routing, core-memory T3 eligibility, reminder
loops, graph pruning, watermarks and locale. Keep expensive inference outside
latency-sensitive capture where the upstream contract requires background work.

### 4. Historical feature gaps

Cover capture/recall, temporal merge lineage, LLM and embedding caches, semantic
lens/continuity, shared pools, graph/entity behavior, feedback/reflection,
reminders/proactive delivery, skill workshop, Obsidian workflows, migrations,
provider support and configuration mapping. Close safe native gaps within these
existing subsystems. Do not invent unrestricted filesystem access, unauthenticated
cold-start delivery or automatic destructive rewrites for superficial parity.

If a gap needs a new host API, separately audited remote code, licensing consent
or expanded authority, report the exact boundary rather than enabling it silently.
Existing Jina v5 nano support does not prove an unaudited Jina v3 loader safe.

### 5. Hermes-specific preservation

Regression coverage must preserve:

- Profile-bound dashboard visibility and refresh when switching agents; both
  main plugin and controls activation checks, with explicit inconsistent states.
- Graphical macOS setup with all/default/individual existing-profile selection,
  explicit activation, readonly inspection and no implicit future-profile setup.
- Embedding/reranking settings, Jina nano/BGE paths, optional existing providers,
  explicit license/download consent and encoder fingerprint/dimension checks.
- Reviewed staged re-embedding, source-drift checks, scoped metadata preservation,
  leases, validated activation, backups, rollback and recovery.
- Idempotent schema migration; tombstones, epistemic cutoffs, ACL metadata and
  private dream/workspace ownership across normal and bulk writers.
- Dashboard/controls confirmations tied to current identity, scope, revision and
  one-use tokens; safe handling of stale requests after profile switches.
- Per-user native job installation, collision avoidance and operator overrides.
- Installer receipts, checksum validation, rollback, package bytecode exclusions
  and immutable signed macOS app bundles (`-I -B` for embedded Python).

## Error handling and security

Use existing path/identifier validation, exact writer selection and atomic
persistence patterns. Keep manual files and unrelated user changes intact.
Storage migrations run in disposable fixtures first; destructive operations
retain archive/audit requirements. Log bounded actionable diagnostics without
credentials, conversation text or cross-profile leakage. Optional inference
failure must not silently lose capture or bypass security checks.

## Verification and delivery

For each changed contract, first reproduce missing/incorrect behavior in a
targeted regression, then test the native reachable path. Verify real LanceDB
schema evolution, restart/retry idempotence, concurrent ownership, empty and
legacy stores, negative authorization cases and migration rollback.

Run complete Python, controls, dashboard and distribution suites, upstream Node
tests, lint, dependency audit, diff checks, wheel and npm-package inspection.
Document upstream/environment failures separately; do not lower an audit gate
because upstream made a CI check informational.

Required platform evidence remains macOS ARM64, Windows ARM64, Windows x64 and
Ubuntu/Linux x64. Preserve existing Linux ARM64 coverage; Intel macOS is excluded
by user decision. Separate build/import/storage tests from real Hermes lifecycle,
model and visible UI acceptance. No command-entry or matrix listing substitutes
for guest output. Any unavailable gate remains explicitly unverified.

Prepare only candidate artifacts with coherent pre-release identifiers and a
manifest identifying both source commits and test results. Existing signing
support stays intact; new signatures/notarization and publication are separate
later gates, not inherited claims from 7.12.7-hermes.4.

Completion requires a reconciled feature matrix, implemented applicable changes,
documented residual host limitations, regression evidence and candidate artifacts.
No blanket 'all features ported' claim while required native contracts remain
partial or unverified. Final review must inspect actual runtime wiring as well
as tests and artifacts.

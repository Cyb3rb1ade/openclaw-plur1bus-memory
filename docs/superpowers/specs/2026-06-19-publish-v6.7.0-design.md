# Release Pipeline: `@cyb3rb1ade/plur1bus-memory` v6.7.0

**Date:** 2026-06-19
**Package:** `@cyb3rb1ade/plur1bus-memory`
**Version:** 6.7.0
**Expected HEAD:** `baf208c` (docs(plan): v6.7.0 release pipeline implementation plan)
**Working directory:** `/root/openclaw-memory-system`

## Goal

Publish v6.7.0 to npm (public), create a GitHub Release with annotated tag, and register the same artifact on ClawHub — all from a single `.tgz` so npm and ClawHub receive identical content.

## Pipeline

### Phase 0 — Final Preflight

Verify auth, git state, and that 6.7.0 is not yet published before touching anything.

```bash
cd /root/openclaw-memory-system

# Git state
git status --short
git log --oneline -8
git rev-parse HEAD
# Expected: baf208c...

# Auth checks
npm whoami
gh auth status
clawhub whoami || true

# Version existence guard — explicit shell guard, safe under set -e
EXISTING="$(npm view @cyb3rb1ade/plur1bus-memory@6.7.0 version 2>/dev/null || true)"
if [ -n "$EXISTING" ]; then
  echo "ERROR: @cyb3rb1ade/plur1bus-memory@6.7.0 already published ($EXISTING). Aborting."
  exit 1
fi
echo "OK: 6.7.0 not yet published."
```

**Gate:** Abort if HEAD is not `baf208c...`, or if `$EXISTING` is non-empty.

### Phase 1 — Tests + Initial Dry-Runs

Validate source before building the artifact.

```bash
npm run lint
npm test
npm pack --dry-run
npm publish --dry-run --access public
```

All four commands must exit 0 before proceeding.

### Phase 2 — Build Artifact

Produce the single `.tgz` that all subsequent steps use.

```bash
rm -rf /tmp/plur1bus-release
mkdir -p /tmp/plur1bus-release
npm pack --pack-destination /tmp/plur1bus-release
ls -lh /tmp/plur1bus-release/*.tgz

TGZ="$(ls -1 /tmp/plur1bus-release/*.tgz | head -1)"
echo "$TGZ"
```

### Phase 2b — Artifact Dry-Run Validation

Validate the exact `.tgz` before any remote operation.

```bash
npm publish "$TGZ" --dry-run --access public
clawhub package publish "$TGZ" --family code-plugin --dry-run
```

Both must exit 0. This confirms npm and ClawHub will accept the same artifact.

### Phase 3 — Push Main + Annotated Tag

Check for existing tag before creating.

```bash
# Tag existence guard
LOCAL_TAG="$(git tag --list v6.7.0)"
REMOTE_TAG="$(git ls-remote --tags origin v6.7.0)"
if [ -n "$LOCAL_TAG" ] || [ -n "$REMOTE_TAG" ]; then
  echo "ERROR: tag v6.7.0 already exists. Aborting."
  exit 1
fi

git push origin main
git tag -a v6.7.0 -m "v6.7.0"
git push origin v6.7.0
```

### Phase 4 — npm Publish

```bash
npm publish "$TGZ" --access public

# Verify
npm view @cyb3rb1ade/plur1bus-memory@6.7.0 version
# Expected: 6.7.0
```

### Phase 5 — GitHub Release

Only runs after Phase 4 exits 0.

```bash
gh release create v6.7.0 \
  --verify-tag \
  --title "v6.7.0" \
  --notes-file RELEASE_6.7.0.md \
  "$TGZ"
```

### Phase 6 — ClawHub Publish

Only runs after Phase 5 exits 0. Uses the same `.tgz`.

```bash
clawhub package publish "$TGZ" --family code-plugin
```

## Error Handling

| Rule | Detail |
|------|--------|
| Stop on any failure | No phase is skipped or retried automatically |
| Version existence gate | Shell guard in Phase 0 — safe under `set -e`; non-zero exit only on conflict |
| No tag overwrite | Shell guard in Phase 3 — checks local and remote before `git tag` |
| GitHub Release after npm | Phase 5 only runs if Phase 4 succeeded |
| ClawHub after GitHub Release | Phase 6 only runs if Phase 5 succeeded |
| No re-publish after npm publish | Once 6.7.0 is on npm, that version is immutable; forward-fix only |
| Single artifact | `$TGZ` used for npm publish, GitHub Release attachment, and ClawHub publish |

## Success Criteria

- `npm view @cyb3rb1ade/plur1bus-memory@6.7.0 version` returns `6.7.0`
- GitHub Release `v6.7.0` exists with `.tgz` attached and `RELEASE_6.7.0.md` as notes
- `clawhub package publish "$TGZ"` exits 0
- npm and ClawHub received the identical `.tgz` artifact

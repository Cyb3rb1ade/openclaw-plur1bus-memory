## Contract and consumer boundary

**Engine contract 1.19.0.** Main supplies through 1.16.0; 1.17.0 (A1) and
1.18.0 (D116 C1) are reserved by parallel work and their APIs are not claimed
here. The live open Engine PR inventory showed no later reservation when this
phase selected 1.19.0. `Engine.contract`, status, schema, frozen TypeScript
contract and conformance agree. `Engine.capabilities.mediaIndex === true`
lets consumers detect this addition without assuming the parallel contracts.

H2 continues against Fakes until the Controller pins the reviewed Engine commit.
The [media contract](../media-embeddings.md) describes:

- `media.index({mediaId, kind, mime, source:{bytes}|{path}, caption?, captionSource?, scope})`;
- `media.search({text? OR likeMediaId?, scope, kinds?, limit?, minScore?, fuseCaptions?})`;
- `media.remove(mediaId)`, `media.setCaption(mediaId,text,source)`, `media.status()`;
- persistent `media.backfill.start({reason})`, `pause()`, `resume()`, `cancel()`;
- trusted `HostCapabilities.mediaPorts.frameExtractor` / `audioDecoder`,
  `mediaSourceRoot`, and coarse `mediaBudget()`.

`scope` is host-derived authorization context, never RPC input accepted without
validation. Media IDs are global per Engine; Harness should namespace them by
agent. Mutations without scope arguments (`remove`, `setCaption`) require
explicit host authorization before calling the Engine. The index is a separate
SQLite store, captions are ordinary LanceDB memories. Text dimensions/provider
remain independent of the media vector space.

**Cloud must remain disabled without Harness Secret lease, Privacy/localOnly
admission and image/video-second budget enforcement.** The existing boolean
`mediaBudget()` is only a coarse backfill gate; it has no item/unit context and
direct index calls do not use it. H1 does not add a new Secret contract or claim
cloud admission. No paid/cloud inference was called during this phase.
